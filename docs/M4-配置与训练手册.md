# M4 配置与训练手册

> 目标：在 Windows + WSL2(Ubuntu) + RTX 4060 Laptop 8GB 上完成
> 「数据构建 → SFT(3B QLoRA) → DPO → 蒸馏(验证链路) → 门禁评测」。
> 所有训练实验记录在 `services/model-training/reports/experiments/<name>/`（config + 数据 sha256 + metrics）。

## 0. 前置检查（Windows）

```powershell
# GPU 在 WSL 内可见
wsl -d Ubuntu -- nvidia-smi --query-gpu=name,memory.total --format=csv
# 建议 WSL 内存 10GB（训练时）：%USERPROFILE%\.wslconfig
# [wsl2] memory=10GB swap=8GB
```

## 1. 一次性环境准备（WSL，约 20–40 分钟，取决于网速）

```powershell
wsl -d Ubuntu -u root -- bash /mnt/c/Users/Liyou/Documents/deepseek/adguard/services/model-training/scripts/setup_wsl_train.sh
```

脚本做四件事：

1. 建 `/root/adguard-train/.venv`（Python 3.12）；
2. 安装 CUDA 版 `torch==2.5.1` + `transformers/peft/trl/datasets/accelerate/bitsandbytes`（阿里云 PyPI 镜像）；
3. 校验 `torch.cuda.is_available()` 与显存；
4. 下载 `Qwen/Qwen2.5-3B-Instruct` 权重到 `/root/models/qwen2.5-3b-instruct`。

**下载来源（实测）**：HuggingFace 镜像 `hf-mirror.com` 单连接约 0.5 MB/s，
**ModelScope 单连接约 11 MB/s**，因此默认用 ModelScope（脚本 `wsl-download-model.sh` 等价逻辑）。

磁盘占用：WSL 约 4 GB（torch+deps）+ 6.2 GB（模型）+ 数据集 <10 MB。

## 4. SFT（QLoRA 4-bit，约 15–30 分钟）

```powershell
wsl -d Ubuntu -u root -- bash /root/adguard-train/run_sft.sh
```

- 配置：`configs/sft_qwen25_3b_qlora.json`（r16/α32、lr 2e-4、2 epochs、max_len 1024、grad accum 8）；
- 输出：`/root/adguard-train/runs/sft-qwen25-3b-qlora-v1/artifacts/final`（LoRA adapter），
  报告写入 `/root/adguard-train/reports/experiments/...`（随后拷回仓库 `services/model-training/reports/`）；
- 卡死/显存不足：把 `max_seq_length` 降到 768、`grad_accum` 提到 16；或在 WSL 里 `nvidia-smi` 确认
  显存被其他进程占用（Windows 桌面程序会占 1–1.6 GB）。

## 5. 评测（门禁）

```powershell
# 基座模型（下界对照）
wsl -d Ubuntu -u root -- bash /root/adguard-train/run_eval.sh none eval eval-base
# SFT 后
wsl -d Ubuntu -u root -- bash /root/adguard-train/run_eval.sh /root/adguard-train/runs/sft-qwen25-3b-qlora-v1/artifacts/final eval eval-sft
```

门禁（见 ADR-0005）：recall ≥0.95、false_positive_rate ≤0.03、wrong_clause_rate = 0、json_parse_rate ≥0.99。

## 6. DPO

```powershell
wsl -d Ubuntu -u root -- bash /root/adguard-train/run_dpo.sh /root/adguard-train/runs/sft-qwen25-3b-qlora-v1/artifacts/final
```

偏好对当前来自合成（规则教师），真实复审偏好对按 ADR-4 在 M6 复核流程上线后替换。
显存不足时：把 `beta` 维持 0.1、`max_length` 降到 768，或退化为 M5 云上执行（R-4 风险预案：DPO 不稳定则回退 SFT+规则融合）。

## 7. 蒸馏（本地验证链路）

```powershell

wsl -d Ubuntu -u root -- bash -c "cd /root/adguard-train && PYTHONPATH=src .venv/bin/python -m adguard_training.distill generate \
  --teacher-adapter runs/sft-qwen25-3b-qlora-v1/artifacts/final \
  --data-dir data/generated --out-dir data/distill --limit 600"
# 2) 学生（0.5B）训练 + 评测；M5 换 7B/8B teacher、3B student 在云 GPU 复跑
```

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `torch.cuda.is_available() == False` | WSL 未装 NVIDIA 驱动透传 / 用 CPU 轮子 | 确认 Windows 驱动 591+；重装 torch（不要 `--index-url .../cpu`） |
| CUDA OOM | 桌面程序占用显存 / seq 太长 | 关浏览器硬件加速；`max_seq_length=768`；`per_device_batch_size=1` |
| pip 下载慢 | 从 pypi.org 拉 CUDA 依赖 | 用阿里云镜像（脚本默认） |
| 模型下载慢 | hf-mirror 单连接限速 | 改用 ModelScope（约 11 MB/s），见 `scripts/wsl-download-model.sh` |
| 训练 loss 不降 | 数据/模板问题 | 先跑 `run_eval.sh none` 看基座是否已会答（基座可能本来就 pass 所有样本） |
| 评测 JSON 解析率低 | 模型输出 markdown/解释 | 检查数据里 assistant 是否严格 JSON；必要时加 system 约束加强句 |
