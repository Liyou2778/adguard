## 2. 环境与口径

| 环境 | 配置 | 用途 |
|---|---|---|
| 本地 WSL2 | RTX 4060 8GB（笔记本） | 0.5B / 合并 3B 链路、535 条服务端门禁、混合判定对比 |
| AutoDL | RTX 4090（vGPU 48GB 可见）、128 vCPU、503GB RAM、50GB 数据盘 | 7B QLoRA SFT → DPO → 合并 → vLLM/SGLang 压测 → 535 条门禁 |
| 阿里云 A10（已停） | A10 24GB，杭州 J | 因 SSH 连通性与库存问题未能开跑（如实记录，未产生训练数据） |

统一口径：
- 推理服务：`vLLM` OpenAI 兼容 API；评测通过 `pipeline /v1/judge` 调用模型（与线上同一路径）；
- 评测集：535 条 held-out（与 SFT 训练集不重叠）；
- 判定口径：recall = TP/(TP+FN)（正样本中判 block 的比例）；误杀率 = FP/(FP+TN)（负样本中判 block）；
- 错引条款率 = 引用条款不在本地规则库/与规则要求不符的比例。

## 4. 混合判定（规则 + 模型）——535 条同栈对比

方法：同一个 pipeline 栈（同一 BGE embedder + 规则目录），分别以「规则-only」与「规则+模型」两种模式跑 535 条，唯一变量是模型第二意见。避免了两套不同检索实现造成的口径差异（该问题已定位并修复）。

| 指标 | 数值 |
|---|---:|
| 规则-only 判定分布 | block 346 / manual 28 / pass 161 |
| 混合判定分布 | block 346 / manual 27 / pass 162 |
| block → block | **346（100% 保留）** |
| **规则 block 被模型降级** | **0** ✅ |
| manual → manual | 26 |
| pass → pass | 160 |
| pass → manual（语义漏检升级人工） | **1** |
| manual → pass（模型确认免责语境） | **2** |
| 模型不可用降级 | 0 |

样本（原始 JSON：`services/model-training/reports/m5/hybrid-eval-535.json`）：
- `eval-00515`：会员积分兑换（规则未命中）→ 模型判违规 → **manual 转人工**，未自动 block；
- `eval-00532`：依据国家规定评定的"最佳创新奖"→ 免责语境经模型确认 → **pass**；
- `eval-00533`：保存期限/最佳食用期 → 免责语境经模型确认 → **pass**。

结论：保守策略成立——规则 block 权威不可被模型推翻；语义漏检不会被静默放行（升级人工）；模型可以确认豁免但无权 block。
