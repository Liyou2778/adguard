# M6 部署包本地验证（无 ECS）

> 目的：在创建 ECS 之前，验证 `deploy/ecs/package-bundle.ps1` 打出的**部署产物**能真实运行，
> 避免把"构建成功但启动失败"的问题带到云上。
> 日期：2026-11-25 ｜ 环境：Windows + WSL2（Ubuntu），复用本地 MySQL/Redis/MinIO/control-plane/pipeline

## 1. 部署包

| 项 | 实测 |
|---|---|
| 命令 | `powershell -File deploy/ecs/package-bundle.ps1 -Version testv1` |
| 产物 | `dist/ecs/adguard-bundle-testv1.tar.gz`（**30.7 MB**） |
| gateway | **13,815,968 字节**，`ELF 64-bit LSB executable, x86-64, statically linked, stripped`（交叉编译 linux/amd64） |
| control-plane.jar | 29,722,400 字节 |
| pipeline | `pipeline-src/adguard_pipeline/`（api.py 等）+ `pipeline-requirements.txt`（不含 torch/BGE，见偏离记录） |
| systemd/deploy | 完整 `deploy/` 目录随包 |

## 2. 运行验证（WSL 内直接跑打包出的 linux 二进制）

环境变量按 ECS 形态布置（与 `deploy/ecs/config/gateway.env.example` 同结构）：
MySQL 127.0.0.1:3307、Redis / MinIO / control-plane / pipeline 走宿主机地址、`GATEWAY_JUDGE_BACKEND=rule`。

| 检查 | 结果 |
|---|---|
| 进程启动 | 2 秒内监听 :18080（日志 `gateway listening`，`audit worker started`） |
| `GET /healthz`（WSL 内） | **200** |
| `GET /healthz`（Windows→WSL IP） | **200** |
| **M1 冒烟（29 项）** | **29/29 PASS**（上传→对象存储→异步判定→查询闭环、规则库+快照、去重、租户隔离、metrics 全通过） |

> 说明：Windows 的 `127.0.0.1` 本地端口转发未覆盖该 WSL 端口，改用 WSL IP `192.168.221.80:18080` 访问；
> 这是本地环境的网络细节，不影响 ECS（ECS 上 systemd + nginx 直接监听本机端口）。

## 3. 结论

- 部署包中的 **linux 网关二进制可运行**，且能与真实 MySQL/Redis/MinIO/控制面/流水线完成完整业务闭环；
- 打包脚本、环境变量结构、pipeline requirements 均验证可用；
- 尚未验证（必须等 ECS）：systemd 单元拉起、nginx 灰度、RDS/OSS 真实凭据、公网安全组。
