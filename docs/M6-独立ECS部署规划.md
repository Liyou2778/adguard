# P2 独立 ECS 部署规划（与 P1 物理隔离）

> 决策（2026-11-22，用户确认）：**P2 不复用 P1 的 ECS**，另建独立实例。
> P1 实例 `i-bp-redacted`（公网 203.0.113.11）保持现状不动；实测 `/healthz` = 200。
> 本文只做规划，**实例在 M6 上线前再创建**（避免闲置计费）。

## 1. 为什么独立实例（而不是与 P1 共机）

| 维度 | 共机 | 独立实例（选定） |
|---|---|---|
| 故障域 | P2 部署/重启影响 P1 线上演示 | 互不影响 |
| 资源 | 2C4G 跑 P1 + Go + Java + Redis 会 OOM | P2 独占 2C4G |
| 预算归属 | 两个项目成本混在一起 | 各算各的，面试讲得清 |
| 面试叙事 | "两个项目挤一台小机器" | "两个环境、同一套工程规范" |
| 成本 | 省一台 | 多约 ¥0.25/h（按量，可随时停） |

**结论**：多花的钱很少（按量 2C4G ≈ ¥0.254/h，停机只收云盘费），换来干净的环境边界，值得。

## 2. 目标拓扑（M6）

```
                    ┌──────────────────────────────┐
  商家/运营 ──HTTP──► │ P2 ECS (2C4G, Alinux3, 40G)  │
                    │  ├─ gateway-go     :8080      │  ← Go 接入层
                    │  ├─ control-plane  :8081      │  ← Java 控制面（JDK21）
                    │  └─ redis:7        :6379      │  ← 队列/限流（本地容器）
                    └───────┬──────────────┬────────┘
                            │内网           │内网
                    ┌───────▼──────┐  ┌────▼─────────┐
                    │ RDS MySQL 8  │  │ OSS          │
                    │ 库 adguard   │  │ 前缀 adguard/ │
                    └──────────────┘  └──────────────┘
                            │
                    ┌───────▼──────────────┐
                    │ GPU 实例（按量，M4/M5）│  ← 训练/vLLM，用完即停
                    └──────────────────────┘
```

- **RDS**：复用现有 Serverless 实例，**另建独立库 `adguard` + 独立账号**（逻辑隔离，零增量成本）。若想彻底物理隔离，M6 可另购一台最便宜 RDS（约 ¥55–228/月起）。
- **OSS**：复用 `copilot-artifacts-ly` 桶，P2 对象全部放 `adguard/` 前缀 + 独立 RAM 策略（只允许该前缀读写）。
- **Redis**：P2 自己的容器（不共用 P1 的），数据互不可见。
- **GPU**：独立按量实例（gn7i，M5 训练/压测时开），与 P2 CPU 机、P1 都不共享。

## 4. 创建清单（你在阿里云控制台操作，约 5 分钟）

1. 地域：**华东1（杭州）**（与 P1/RDS 同地域，才能走内网）
2. 规格：`ecs.e-c1m2.large`（2 vCPU / 4 GiB）
3. 镜像：**Alibaba Cloud Linux 3.2104 LTS 64位**（与 P1 一致，运维命令相同）
4. 系统盘：ESSD Entry **40 GiB**
5. 网络：与 P1 同 VPC（`vpc-redacted...`）与同交换机；**新建独立安全组** `sg-adguard`，入方向只放：
   - 22/tcp（SSH，来源：你的公网 IP）
   - 8080/tcp（网关，来源：你的公网 IP；正式演示再考虑 SLB）
   - 8081/tcp（控制面，**仅调试期**，M6 后期关闭公网）
   - ICMP
6. 登录方式：**密钥对**（可复用 P1 的 `copilot-key.pem`，或新建 `adguard-key.pem`；密码登录不要开）
7. 计费：**按量付费**；设置"节省停机模式"（不演示时停机省钱）
8. 创建后把 **实例 ID + 公网 IP** 发我

## 5. 创建后由我完成的配置（自动化脚本，M6 时执行）

1. SSH 基线：确认密钥登录、禁用密码、记录系统指纹
2. `dnf install docker-ce`（或 podman）→ 启动 → 配置镜像加速
3. 安装 JDK 21（Temurin/Microsoft，清华或华为镜像）
4. 建 `/opt/adguard/{bin,config,data,logs}`，600 权限放 `config/.env`
5. 部署方式（M6 定稿二选一）：
   - **systemd + 二进制**（轻量，4G 内存最省）：`gateway`（Go 单二进制）+ `control-plane`（Java jar）+ `redis` 容器
   - **docker compose**（一致性好，占内存略多）：三个容器 + compose 文件
6. 健康检查 + 开机自启 + 日志轮转（journald/logrotate）
7. 冒烟：`scripts/smoke-m1.ps1` 改指向公网 IP 重跑；M6 增加灰度与回滚演练
8. 写《P2 生产部署记录》，与 P1 的部署记录同格式

## 7. 与 P1 的隔离边界（验收时逐条演示）

| 资源 | P1 | P2 | 隔离手段 |
