## 1. 背景与问题定义

### 1.1 业务背景

互联网平台的商业化投放每天产生海量营销素材（图文、短视频、落地页）。素材若含绝对化用语、虚假宣传或图文不一致，平台与商家都面临行政处罚与舆情风险。

### 1.2 法律与监管依据〔L1〕

| 依据 | 关键内容 |
|---|---|
| 《广告法》第九条第（三）项 | 禁止"国家级""最高级""最佳"等绝对化用语 |
| 《广告法》第五十七条 | 违者罚款 **20 万–100 万元** |
| 《广告绝对化用语执法指南》（2023 年第 6 号） | 市监总局统一执法口径 |
| 2025 年全国查处广告违法案件 | **4.45 万件**，罚没 **2.52 亿元**〔L1〕 |
| 2026 上半年 | **20302 件**，罚没 **1.05 亿元**〔L1〕 |
| 绝对化用语行政处罚案例 | 检索可得 **4000+ 个**〔L2〕 |

### 1.3 现状 SOP

```
商家提交素材 → 机器初审（关键词+图像识别）→ 通过/拦截/存疑
  → 人工复审 → 判定 + 整改通知 → 商家申诉 → 复核 → 规则库维护
```

### 1.4 痛点

| # | 痛点 | 后果 |
|---|---|---|
| P-1 | 极限词变体绕过（拼音、拆字、谐音、emoji 间隔、零宽字符） | 关键词库永远追不上，漏放 |
| P-2 | 图文不一致难查（图说"进口"、文案写"国产"） | 纯文本与纯图像审核都发现不了 |
| P-3 | 新规上线到规则生效有滞后窗口 | 窗口期全量漏放 |
| P-4 | 拦截结论无条款依据 | 商家不服，申诉量堆高 |
| P-5 | 人工复审成本高 | 只能靠人盯，规模上不去 |

### 1.5 为什么现有方案不够

| 方案 | 问题 |
|---|---|
| 纯关键词库 | 变体绕过；误杀高；无语境判断 |
| 纯大模型 API | 成本无法承载日均百万级；数据出内网违规 |
| 通用 OCR + 规则 | 图文一致性判不了；条款依据无法定位 |

## 2. 产品定位与目标

### 2.1 一句话定位

> 让百万级营销素材在分钟级被判，并且**罚得有依据**。

### 2.2 目标用户

| 角色 | 诉求 |
|---|---|
| 内容风控审核员 | 初审准确率高，减少复审量 |
| 商业化运营 | 拦截理由清晰，能向商家解释 |
| 商家 | 知道违反了哪一条、改哪里 |
| 法务/合规 | 判定可追溯、可出具依据 |
| 平台管理者 | 成本可控、新规能快速生效 |

### 2.3 成功指标

| 指标 | 目标 | 类型 |
|---|---|---|
| 违规召回率 | ≥ 0.95 | 〔L5〕 |
| 误杀率 | ≤ 0.03 | 〔L5〕 |
| 条款级依据命中率 | 100% | 〔L5〕 |
| P99 审核时延 | ≤ 60s | 〔L5〕 |
| 单条推理成本 | 有实测基线 | 〔L5〕 |
| 规则热更新生效时延 | ≤ 5 min | 〔L5〕 |
| 蒸馏后 vs 教师 召回下降 | ≤ 3pt | 〔L5〕 |

### 2.4 非目标

| 非目标 | 理由 |
|---|---|
| 替代人工终审 | 责任在人，AI 只出初审 |
| 舆情研判 | 属另一个域 |
| 侵权/版权判定 | 需专业权利链核查 |
| 视频内容语义深度理解 | 本期聚焦图文与文案 |

## 4. 核心流程

```
素材上传
  → [FR-1] 接入与校验（分片、格式、大小、病毒扫描）
  → [FR-2] 解析（OCR / 版面 / 落地页渲染）
  → [FR-3] 变形归一化
  → [FR-4] 条款级检索（规则树 + 向量 + BM25 + rerank）
  → [FR-5] 模型判定（小模型）
  → [FR-6] 图文一致性校验
  → [FR-7] 判定合成（规则 + 模型）
  → [FR-8] 条款级依据生成
  → [FR-9] 结论输出 / 转人工
  → [FR-10] 申诉与回流
  → [FR-11] 训练与迭代
```

## 5. 功能需求

### FR-1 素材接入 `P0`
- 支持图片（jpg/png/webp）、视频（mp4）、文本、落地页 URL
- 分片上传 + 断点续传；单文件上限可配
- **AC**：超限拒绝；重复上传按 digest 去重；上传成功返回 asset_id

### FR-2 多模态解析 `P0`
- OCR 抽文字 + bbox；版面分析识别标题/正文/角标；落地页抓取渲染后截图 + DOM 文本
- **AC**：OCR 失败时有降级路径并标记；解析结果含坐标

### FR-3 变形归一化 `P0`
- 处理：拼音、拆字/异体字、谐音、emoji 间隔、零宽字符、全半角、繁简
- **AC**：变体测试集（≥1000 条）归一化后命中率 ≥ 0.95；归一化保留原文坐标映射

### FR-4 条款级检索 `P0`
- 多路召回（向量 + BM25 + 规则树 + 家族词典）+ rerank + 阈值过滤
- **AC**：召回结果必须是条款粒度；chunk 内容变更后旧结果被丢弃

### FR-5 模型判定 `P0`
- 小模型输出：是否违规、违规类别、置信度
- **AC**：单条 P99 ≤ 60s；模型版本与规则快照写入判定记录

### FR-6 图文一致性 `P1`
- 抽取断言三元组（主体-属性-值），检测互斥
- **AC**：构造的图文冲突样本检出率 ≥ 0.9

### FR-7 判定合成 `P0`
- 规则命中 + 模型判定合并；高风险规则优先
- **AC**：同一输入在相同规则快照下判定稳定（可复现）

### FR-8 条款级依据 `P0`
- 输出 rule_id、法条号、罚则区间、原文 span/bbox
- **AC**：每条违规都必须有 rule_id 与定位；无依据的违规不得输出

### FR-9 结论与转人工 `P0`
- 三态输出：pass / block / manual
- **AC**：manual 必须给出转人工原因

### FR-10 申诉与回流 `P1`
- 商家申诉 → 复核 → 生成偏好对
- **AC**：复核结论自动进入 feedback_pair，且标记是否已用于 DPO

### FR-11 训练与迭代 `P0`
- SFT → DPO → 蒸馏；每次训练产出评测报告
- **AC**：新模型上线前必须过门禁（召回不降、误杀不升、条款命中 100%）

### FR-12 规则热更新 `P0`
- 规则新增/修改 → 草稿 → 灰度 → 生效；下发快照
- **AC**：生效时延 ≤ 5 min；无需重建索引；可回滚

### FR-13 多租户与配额 `P1`
- 租户隔离、调用配额、成本归集
- **AC**：跨租户数据不可见；配额超限拒绝

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | P99 ≤ 60s；批量吞吐按 GPU 容量给出基线 |
| 可用性 | ≥ 99.5%；分级降级（模型不可用→退规则） |
| 安全 | 私有化部署；数据不出内网；上传文件病毒扫描 |
| 合规 | 判定依据可导出；审计日志留存 |
| 可复现 | 判定绑定规则快照 + 模型版本 |
| 成本 | 单条成本可观测；支持按租户归集 |

## 7. 约束与假设

### 7.1 硬件约束（本机实测）

| 约束 | 现状 | 影响 |
|---|---|---|
| GPU | **RTX 4060 Laptop 8 GB**（sm_89） | **7B LoRA SFT 不可行**；只能 3B QLoRA 或 1.5B，或租云 GPU |
| 内存 | 15.2 GB | 本地不宜同时起推理服务与全栈 |
| 磁盘 | C: 111 GB 可用 | 模型权重与数据集需控制体积 |

**结论**：P2 的训练链必须分两条路——
- **本地**：3B QLoRA 小规模验证（跑通链路、验证指标）
- **云 GPU**：7B/8B 全量 SFT + DPO + 双引擎压测（租用，按小时计费）

### 7.2 业务约束

- 私有化部署，不调用任何公有云模型 API
- 素材属商家私有资产，不得外传
- 判定必须可解释、可申诉

### 7.3 假设

- 有历史人工判例可用于构造标注集与偏好对
- 有 GPU 或可租用云 GPU
- 规则库初期可由公开法规 + 平台规则构建

## 8. 总体架构

```
接入层  Go + Eino：上传、签名 URL、限流
控制面  Java + Spring：多租户 / 规则库 / 审批 / 配额 / 审计
知识面  WeKnora：解析 / 条款级切分 / 混合检索 / rerank / 增量索引
模型面  Python：SFT / DPO / 蒸馏 / 评测 / vLLM·SGLang 推理
多模态  OCR / 版面分析 / 落地页渲染
数据面  MySQL / Redis / MQ / MinIO / 向量库
观测面  训练指标 / 推理 TTFT·吞吐·成本 / 检索 NDCG / 业务召回
```

## 11. 关键设计决策（ADR）

| ID | 决策 | 理由 |
|---|---|---|
| ADR-1 | 规则结构化为「条文-词族-判定条件-罚则」 | 新规只改数据不改代码 |
| ADR-2 | 归一化对抗前置，粗筛只求召回 | 漏放不可挽回，误报可后置处理 |
| ADR-3 | 判定绑定规则快照 | 保证半年后可复现"当时为什么这么判" |
| ADR-4 | DPO 偏好对来自复审裁决 | 真实偏好，非造数据 |
| ADR-5 | 蒸馏到 3B 并双引擎压测 | 成本驱动，非技术偏好 |

## 12. 实施计划（每一步怎么做）

### M0 环境就绪（0.5 人周）
1. 启动 Docker Desktop
2. 确认 GPU 可用（`nvidia-smi`，8 GB）
3. 决定训练路径：本地 3B QLoRA / 云 GPU 7B
4. 安装 Go 1.22+、JDK 21（当前 25 可能不兼容 Spring Boot 3）

**验收**：`docker info` OK；`nvidia-smi` OK；`java -version` 为 21

### M1 骨架（2 人周）
1. Go 接入网关（上传/分片/签名 URL）
2. Java 控制面骨架（租户/规则 CRUD/审批）
3. compose 起 MySQL/Redis/MinIO/向量库
4. CI

**验收**：上传→存储→查询闭环

### M2 法规结构化（2.5 人周）
1. 规则模型与表结构
2. 变体归一化管线（7 类变形）
3. 变体测试集（≥1000 条）
4. 条款解析器（从法规文本抽结构）

**验收**：变体命中率 ≥ 0.95；条款解析准确率人工抽检 ≥ 90%

### M3 知识工程（2.5 人周）
1. 条款级切分（按"第X条"锚点）
2. 多路索引 + rerank 接入
3. 增量索引与 chunk revision 校验
4. 检索评测（NDCG@10 / Recall@K）

**验收**：条款级召回达到设定基线；增量更新后无脏召回

### M4 模型工程（3 人周）
1. 标注集（3k 违规 + 3k 合规 + 1k 边界）
2. SFT（先 3B 本地跑通，再上云跑 7B）
3. DPO（偏好对来自复审）
4. 蒸馏（教师→3B）
5. 评测与门禁

**验收**：召回 ≥ 0.95、误杀 ≤ 0.03、条款命中 100%

### M5 推理与压测（1.5 人周）
1. vLLM 部署 3B
2. SGLang 对照
3. 吞吐/TTFT/成本实测
4. 容量结论

**验收**：一份可引用的压测报告

### M6 上线（1.5 人周）
1. K8s 部署 + GPU 节点池
2. 规则灰度生效
3. 模型灰度（5% 流量）
4. 回滚演练

**验收**：灰度与回滚可执行
