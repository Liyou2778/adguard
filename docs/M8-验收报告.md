## 1. 交付内容

| 能力 | 实现 |
|---|---|
| 身份与角色 | `app_user`（tenant_id、username、bcrypt 密码、role=owner/member/reviewer/admin、status），Flyway V5 |
| 登录态 | HS256 JWT（网关与控制面共享密钥 `ADGUARD_JWT_SECRET`），12h 过期，claims 含 tenant/role |
| 注册/登录 | `POST /auth/register`（创建租户 + owner）、`POST /auth/login`、`GET /auth/me`、`POST /auth/password` |
| 用户管理 | `/admin/users`（列表/创建/改角色/禁用/重置密码，禁止停用最后一个管理员） |
| 租户与配额管理 | `/admin/tenants`（创建/列表/改配额/停用） |
| 管理台 | `/admin-ui/` 单页管理台：登录、申诉复核、用户、租户配额、账单导出、规则激活 |
| 商家申诉 | `POST /api/v1/appeals`（仅 block/manual 可申诉；同一判定最多 1 个 open 申诉，DB 生成列唯一索引保证） |
| 复核 | `/admin/appeals` 列表/详情（含 judgment、violations、asset、bbox 证据）；`PATCH /admin/appeals/{id}/review` 显式选择 final_decision |
| DPO 回流 | 复核完成即写 `feedback_pair`（chosen=复核结论，rejected=原判定+证据），`used_in_dpo=0`；`/admin/feedback-pairs` 查询与 `mark-used` 供训练脚本使用 |
| 审计 | `audit_log` 记录注册、建用户、改租户、申诉、复核、标记训练使用等动作 |
| 自动化鉴权 | `ADGUARD_ADMIN_KEY`（X-Admin-Key）供冒烟/运维调用，生产必开 `ADGUARD_AUTH_REQUIRED=true` |

## 3. 关键设计

- **租户来源唯一**：商户 API 的 tenant 取自 JWT claim，不接受 query/body 覆盖；管理端跨租户操作需 admin 角色。
- **申诉状态机**：`open → accepted（改判）| rejected（维持原判）`；`original_decision` 与 `final_decision` 同时落库，便于审计和训练区分。
- **回流即证据**：`chosen/rejected` JSON 保存决定、理由与完整 violations（条款/罚则/bbox），训练侧可直接消费。
- **开发/生产双模式**：`ADGUARD_AUTH_REQUIRED=false` 仅限本地开发（隐式 admin），ECS 上为 `true`，冒烟通过 X-Admin-Key 自动化。

## 4. 已知限制

| 项 | 说明 |
|---|---|
| 用户体系范围 | 无邮件/短信找回、无 SSO/LDAP；密码重置由管理员执行并一次性返回新密码 |
| 管理台 | 极简单页（无构建链、无复杂权限 UI）；审核证据以表格/JSON 呈现 |
| 登录风控 | 无验证码、无登录限速（网关层统一限速）；生产建议在 nginx/WAF 增加 |
| JWT 吊销 | 退出仅客户端丢弃 token；租户/用户禁用后需等 token 过期（≤12h），可在网关加 Redis 黑名单后续增强 |

## 5. 结论

FR-10 的「商家申诉 → 复核 → 偏好对生成 → 标记是否用于 DPO」闭环在本地与云上均通过自动化验收，配套用户/角色/管理台可支撑真实运营。
