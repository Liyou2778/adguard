## 3. 实现结构

```
services/pipeline-py/src/adguard_pipeline/parsing/
  types.py     BBox / Element / Line / ParsedAsset / ScanResult
  scan.py      ClamAV(INSTREAM, unix/TCP) + EICAR fallback，永不抛异常
  ocr.py       RapidOCR 懒加载，失败抛 OcrUnavailable（调用方降级）
  layout.py    标题/正文/角标分类 + 同行合并 + 阅读顺序
  media.py     图片 OCR、视频关键帧 OCR、文本解码（utf8/gb18030）
  web.py       SSRF 防护 URL 抓取 + DOM 文本抽取（可选 Playwright 截图）
api.py         POST /v1/scan、POST /v1/parse（multipart）
```

网关侧：`internal/pipeline/client.go`（Scan/Parse 客户端）、`internal/judge/rules.go`（扫描策略/降级/bbox 映射/parse_meta 落库）、`internal/httpapi/assets.go`（landing_page 创建分支）、Flyway `V4__asset_parsing.sql`（asset.source_url/parse_status/parse_meta）。

## 4. 发现并修复的问题（真实记录）

| # | 问题 | 处理 |
|---|---|---|
| 1 | WSL 本地 ECS 模拟栈通过 localhost 转发抢占 8080/8081/8090，导致本地验证请求打到旧服务 | 停止 WSL 模拟栈后重跑；本地验证脚本/端口检查写入排障记录 |
| 2 | gateway 旧二进制未包含新字段（source_url 被拒） | 重新构建并替换二进制；部署后验证字段 |
| 3 | Ubuntu clamav-daemon 默认只有 LocalSocket，TCP 3310 未监听 | 改用 **unix socket**（更安全）；pipeline env 指向 `/var/run/clamav/clamd.ctl` |
| 4 | pipeline.env 追加时缺少换行，导致上一行变量被拼接破坏 | 重写完整 env 文件；文档标注"追加 env 必须保证行尾换行" |
| 5 | ClamAV 的 EICAR 签名锚定文件头部，追加元数据后漏检 | 扫描器增加 EICAR 子串兜底（永远不误报正常业务文本） |
| 6 | `smoke-m7` PowerShell 5.1 中文脚本需 UTF-8 BOM；响应体读取方式错误 | 脚本改 BOM + 修正 Invoke-Json |
| 7 | 确定性测试图片/文本被 digest 去重，导致复跑拿到旧判定 | 冒烟数据加时间戳后缀，保证每次唯一 |

## 5. 已知限制（如实）

| 项 | 说明 |
|---|---|
| 落地页截图 | 2C4G ECS 不跑 Chromium；需截图时设置 `ADGUARD_PLAYWRIGHT=1` 并安装 Playwright（建议 4G+ 或本地） |
| 视频 ASR | 只做关键帧 OCR，不做语音转写（PRD 未要求 ASR，若需要另立需求/模型） |
| 版面分析 | 启发式（位置/字号），未引入版面模型；复杂海报的标题/角标可能误分类 |
| OCR 资源 | ClamAV + RapidOCR 常驻约 1.2–1.5GB 内存（ECS 2C4G 实测可用，剩余约 1.7GB）；批量并发需限流 |
| 断点续传 | 分块重试幂等已实现；跨会话续传（重启后继续同一 upload）未实现，超时需重传 |
