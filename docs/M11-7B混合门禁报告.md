# M11 验收报告：真实 7B 混合判定门禁（规则 + Qwen2.5-7B-SFT）

> 日期：2026-11-25 ｜ 里程碑：M11（模型闭环复验）
> 环境：AutoDL vGPU-48GB（RTX 4090 48G，西北B区 456机，¥2.88/时）＋ WSL2 本地评测栈
> 模型：`merged-sft-7b`（M5 云端 QLoRA SFT 合并产物，15GB，从旧实例克隆 = 原权重未重训）
> 推理：vLLM 0.6.3.post1 + torch 2.4.0+cu121 + driver 580.95
> 结论：**门禁不通过，不切换生产**；但安全指标（0 降级 / 0 误杀 / 0 错引 / 0 模型不可用）全部达标，已定位主要瓶颈为规则/检索召回上限（93.01%）。

## 1. 方法（与生产同构）

- 将 AutoDL 上的 7B-SFT 模型用 vLLM 起 OpenAI 兼容服务 `:8100`（48G 显卡、max-model-len 1024、fp16）；
- WSL 本地跑**同一套 pipeline**（同样的 BGE 检索索引与规则库）两份实例：
  - `:8092` rule-only；
  - `:8091` hybrid（`ADGUARD_MODEL_JUDGE_URL` 经 SSH 隧道指向云端 vLLM）；
- 对 535 条 held-out 评测集（gold 决策 + gold 条款）分别跑两个实例，比较决策、转人工率、误杀、条款引用与安全策略；
- 模型确实被逐条调用：vLLM 日志共 **1072 次 chat/completions = 2 轮 × 536 次**（每轮 535 行 + 预热），无超时/不可用。

## 2. 结果

### 2.1 规则 vs 7B hybrid（同栈 535 条）

| 指标 | rule-only | hybrid（7B） |
|---|---|---|
| decisions | block 346 / manual 28 / pass 161 | block 346 / manual 28 / pass 161 |
| recall | 0.9301 | **0.9301** |
| false positive rate | 0.0000 | **0.0000** |
| wrong clause rate | 0.0000 | **0.0000**（0/346） |
| manual rate | 5.23% | **5.23%** |
| model unavailable rows | — | **0** |
| rule block downgraded | — | **0** |

转人工迁移：`block→block 346`、`manual→manual 28`、`pass→pass 161`；**没有任何一条规则 block 被模型降级**，也没有模型新增升级/豁免确认。

### 2.2 与 M5 3B 代理对比（同数据）

| 模型 | manual | manual→pass（免责确认） | wrong citation | 备注 |
|---|---|---|---|---|
| 3B merged（M5） | 27 / 535 = 5.05% | 2 | 0 | 3B 在高风险豁免语境上更"放行" |
| **7B merged（本轮）** | **28 / 535 = 5.23%** | **0** | **0** | 7B 更保守：把"最佳创新奖 / 最佳食用期"等仍判为违规→保持人工 |

vLLM 调用计数与逐行理由确认：7B 对每行都给出了判定，但保守策略下（规则 block 权威、模型不能单独 block），模型无法提升召回，只影响 pass/manual 之间的转人工。

## 3. 门禁判定（如实）

| 维度 | 门禁 | 实测 | 结论 |
|---|---|---|---|
| 安全：规则 block 不被降级 | == 0 | 0 | ✅ |
| 安全：模型不可用 | == 0 | 0 | ✅ |
| 质量：误杀 FPR | ≤ 0.03 | 0.0000 | ✅ |
| 质量：条款错引 | == 0 | 0.0000（0/346） | ✅ |
| 质量：召回 | ≥ 0.95 | **0.9301** | ❌（规则/检索上限，非模型可补） |
| 质量：人工率 | ≤ 5% | **5.23%** | ❌（略超） |

**总判定：不通过 → 生产保持 `GATEWAY_JUDGE_BACKEND=rule`，不开启 hybrid。** 这与"门禁通过前不切生产"的原则一致。

## 4. 关键结论与下一步

1. **召回瓶颈在规则/检索**：26 条 gold-block 漏检全部来自规则/检索未命中，模型按保守策略不能补 block；提升召回应先扩充规则覆盖/检索召回，而不是换模型。
2. **7B 更保守**：免责语境下 7B 倾向判违规（3B 有 2 条确认豁免，7B 为 0），导致 manual 率略升；若未来上 hybrid，需补充"豁免/免责语境"训练样本或调策略提示。
3. **安全基线已建立**：0 降级、0 误杀、0 错引、0 模型不可用，说明混合链路工程上是可用的，只差质量门禁。
4. 建议：
   - 先做规则/检索召回专项（目标：gold-block 漏检 ≤ 13 条，使 recall≥0.95）；
   - 再评估 hybrid（可把 manual 率 SLO 从 5% 调整到 6%，或补豁免样本后复跑本门禁）；
   - 本轮未切换生产、未改 ECS 配置；ECS 仍运行 m10。
