## 2. 产品定义（摘自 PRD，不要改）

**一句话定位**：把营销素材合规审核从"人看人判"变成"机器粗筛 + 条款级依据 + 人工只做复核"。

**目标用户**：互联网平台的营销/广告审核团队。

**核心痛点**：人工审核慢、标准不一致、无法给出条款级依据、新规上线滞后。

### 13 个功能需求（FR）

| FR | 名称 | 优先级 |
|---|---|---|
| FR-1 | 素材接入 | P0 |
| FR-2 | 多模态解析（OCR/版面） | P0 |
| FR-3 | **变形归一化**（7 类变形） | P0 |
| FR-4 | **条款级检索** | P0 |
| FR-5 | **模型判定** | P0 |
| FR-6 | 图文一致性 | P1 |
| FR-7 | 判定合成 | P0 |
| FR-8 | 条款级依据（span/bbox 定位） | P0 |
| FR-9 | 结论与转人工 | P0 |
| FR-10 | 申诉与回流 | P1 |
| FR-11 | **训练与迭代** | P0 |
| FR-12 | 规则热更新 | P0 |
| FR-13 | 多租户与配额 | P1 |

### 五条 ADR（已定，不要重新讨论）

| ID | 决策 | 理由 |
|---|---|---|
| ADR-1 | 规则结构化为「条文-词族-判定条件-罚则」 | 新规只改数据不改代码 |
| ADR-2 | 归一化对抗前置，粗筛只求召回 | 漏放不可挽回，误报可后置处理 |
| ADR-3 | 判定绑定规则快照 | 保证半年后可复现"当时为什么这么判" |
| ADR-4 | DPO 偏好对来自复审裁决 | 真实偏好，非造数据 |
| ADR-5 | 蒸馏到 3B 并双引擎压测 | 成本驱动，非技术偏好 |

3. **诚实数字**：报告里写清测量条件、样本量、已知局限；发现异常先怀疑测法
4. **写文档**：每个里程碑产出 `docs/xxx报告.md`（部署记录、容量报告、评测方法论）
5. **测试全绿**：P1 是 105 个测试，P2 同样要求

### P1 踩过的坑（P2 别再踩）

| 坑 | 教训 |
|---|---|
| 表主键用 `step_id` 而非 `(task_id, step_id)` | 并发下租约互相顶掉 → **任何协调状态都要带业务主键** |
| `.env` 解析器不剥引号 | 密码"正确"却认证失败，浪费 1 小时 → **多套解析器必须行为一致** |
| dry-run 跳过 DDL 执行 | "验证通过"但什么都没验证 |
| 注释里有分号，先切分后去注释 | DDL 被切成无效 SQL → **先去注释再切分** |
| 记忆写入包含了召回附录 | 记忆自我污染，指数级放大 → **写入侧必须剥离** |
| PowerShell 读写文件破坏中文编码 | 改文件用 edit 工具，不要 `Get-Content`/`Set-Content` 往返 |
| 压测打了生产库 | 留下 3008 个垃圾任务 → **压测用独立库** |
