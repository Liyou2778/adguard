> 目标：一台 Windows 开发机，从零到跑通「上传 → 存储 → 查询」闭环，并执行验收脚本。
> 全部依赖均已本地化：MySQL/Redis/MinIO 走 Docker；Go/Java/Python 用本机工具链。

## 1. 起中间件（MySQL 8 + Redis 7 + MinIO）

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev-up.ps1
```

| 服务 | 地址 | 凭据 | 说明 |
|---|---|---|---|
| MySQL 8.0 | `127.0.0.1:3307` | `adguard/adguard`，库 `adguard` | 宿主机 3306 已被本机 MySQL57 占用，故映射 3307 |
| Redis 7 | `127.0.0.1:6379` | 无 | 审核任务队列（Stream） |
| MinIO（S3 兼容） | API `127.0.0.1:9000`，控制台 `:9001` | `minioadmin/minioadmin` | 桶 `adguard-assets` 由 `minio-init` 自动创建 |

**表结构由谁建**：Java 控制面启动时用 Flyway 执行 `services/control-plane-java/src/main/resources/db/migration/V1__init.sql`。
网关（Go）只读写数据、不做 DDL——单一起源，避免两套迁移打架。

## 4. 一条完整的手工请求链（curl）

```powershell
$tenant = 'demo-platform'

# 4.1 建规则 -> 激活 -> 快照
curl.exe -s -X POST http://127.0.0.1:8081/admin/rules -H "X-Tenant-Id: $tenant" `
  -H "Content-Type: application/json" --data-binary "@examples/rule-adv-law-art9-3.json"

curl.exe -s -X POST "http://127.0.0.1:8081/admin/rules/ADV-LAW-ART9-3/activate" -H "X-Tenant-Id: $tenant"

# 4.2 建上传会话
curl.exe -s -X POST http://127.0.0.1:8080/api/v1/assets -H "X-Tenant-Id: $tenant" `
  -H "Content-Type: application/json" `
  -d '{\"filename\":\"creative.png\",\"size_bytes\":10485760,\"type\":\"image\",\"chunk_size\":5242880}'

# 4.3 传分片（用真实文件的前 5MB / 后 5MB）
curl.exe -s -X PUT "http://127.0.0.1:8080/api/v1/assets/<asset_id>/chunks/0" `
  -H "X-Tenant-Id: $tenant" -H "Content-Type: application/octet-stream" --data-binary "@part0.bin"

# 4.4 完成 -> 202，随后异步判定
curl.exe -s -X POST "http://127.0.0.1:8080/api/v1/assets/<asset_id>/complete" -H "X-Tenant-Id: $tenant"

# 4.5 查判定（轮询 GET asset 直到 latest_judgment_id 出现）
curl.exe -s "http://127.0.0.1:8080/api/v1/assets/<asset_id>" -H "X-Tenant-Id: $tenant"
curl.exe -s "http://127.0.0.1:8080/api/v1/judgments/<judgment_id>" -H "X-Tenant-Id: $tenant"
```

完整字段与错误码见 [M1 接口契约](../api/m1-contract.md)。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `create upload failed: Error 1146 Table ... doesn't exist` | 控制面没启动过，Flyway 未建表 | 先启动控制面并确认 health=UP |
| `readyz` 503 `schema not ready` | 同上 | 同上 |
| `docker compose up` 很慢 | 首次拉取镜像（走 docker.1panel.live 加速） | 等待；或先 `docker pull mysql:8.0` |
| 分片 `400 INVALID_CHUNK_SIZE` | 非最后一片必须恰好 `chunk_size` 字节 | 检查客户端切分逻辑 |
| `409 INCOMPLETE_UPLOAD` | 还有分片没传 | 重传缺失 index |
| 网关启动卡在 `dependency not ready` | MySQL/Redis/MinIO 未起 | 先执行 `dev-up.ps1` |
| 判定一直是 `queued` | worker 未启用或 Redis 不通 | 检查网关日志；确认 `GATEWAY_WORKER_ENABLED=true` |

## 7. 环境守护：WSL 空闲关机导致 MySQL 连接拒绝（2026-11-23 踩坑）

**现象**：网关返回 500 `failed to create upload`，日志 `dial tcp 192.168.221.80:3307: ... actively refused`；
`journalctl -u adguard-mysql` 显示 MySQL 被反复 stop/start。

**根因**：WSL2 在无活动会话时会自动关闭发行版（VM idle shutdown）。如果 **keepalive 进程不在了**，
每条 `wsl -d Ubuntu ...` 命令都相当于一次冷启动，MySQL 要 ~40–60 秒才就绪，期间请求全部失败。

**恢复**（Windows 侧执行一次，保持进程常驻）：

```powershell
Start-Process -FilePath "wsl.exe" -ArgumentList @("-d","Ubuntu","-u","root","--","sleep","infinity") -WindowStyle Hidden
```

**验证**：`wsl -d Ubuntu -u root -- bash -c "pgrep -af 'sleep infinity'; systemctl is-active adguard-mysql"`，
再等 60 秒重复一次，`uptime -s` 不应变化；三服务 healthz 均 200 后重跑 `smoke-m1.ps1` / `smoke-m3.ps1`。

**排查命令**：
`Get-Content .tmp\logs\gateway.out.log -Tail 20`；`journalctl -u adguard-mysql -n 50 --no-pager`。
