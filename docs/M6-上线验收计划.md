## 3. 部署步骤（我执行）

```bash
# 3.1 基线（幂等）
scp -i key deploy/ecs/setup-ecs.sh root@<IP>:/root/
ssh root@<IP> "bash /root/setup-ecs.sh"          # 预期最后一行 SETUP_DONE
# 3.2 同步仓库（或仅 deploy/ 目录 + 构建产物）
rsync -az -e "ssh -i key" ./ root@<IP>:/opt/adguard-src/
# 3.3 安装 systemd units
ssh root@<IP> "bash /opt/adguard-src/deploy/ecs/install-units.sh /opt/adguard-src/deploy/ecs"
#   预期 UNITS_INSTALLED
# 3.4 写环境变量（密钥只在服务器，chmod 600）
scp config/*.env root@<IP>:/opt/adguard/config/ && ssh root@<IP> "chmod 600 /opt/adguard/config/*.env"
# 3.5 首次发布 bundle（gateway + control-plane.jar + pipeline）
#   由本的 deploy 脚本打包上传 → remote-deploy-bundle.sh
# 3.6 启动并健康检查
ssh root@<IP> "systemctl start adguard-control-plane adguard-pipeline adguard-gateway-stable"
ssh root@<IP> "curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8080/healthz"   # 预期 200
```

## 5. 灰度与回滚演练（验收核心）

| 步骤 | 命令 | 证据 |
|---|---|---|
| 发布 v2 到 canary（10%） | `deploy-gateway.ps1 -EcsHost <IP> -SshKey key -Version v2` | canary healthz 200；nginx 访问日志 canary/stable 比例 ≈10/90 |
| 50% | 脚本自动继续 | healthz 200 |
| 100% | 脚本自动继续 | healthz 200 |
| cutover | 脚本自动：promote → nginx 0% → 停 canary | `STABLE_HEALTHY`；healthz 200 |
| 回滚演练 | `deploy-gateway.ps1 -EcsHost <IP> -SshKey key -Rollback` | `ROLLBACK_OK`；版本号回退；healthz 200 |

**验收门槛**：每档灰度 public healthz 均 200；cutover 后无 5xx 窗口（观察 1 分钟 `/metrics` 错误计数）；回滚 ≤30s 内恢复 200。

## 6. 已知偏离与风险（必须写进部署记录）

| 项 | 偏离/风险 | 处理 |
