## 四、环境偏离与原因（诚实记录）

### 4.1 MySQL 未用 compose 镜像，改用 WSL 独立实例

| 项 | 事实 |
|---|---|
| 计划 | `deploy/docker-compose.yml` 的 `mysql:8.0`（端口 3307） |
| 实际 | `docker.1panel.live` 与 `docker.m.daocloud.io` 两个加速站拉取 `mysql:8.0` **均卡死**：第二次下载在 34.6 MB/36.7 MB 处停滞，磁盘写入 **0 MB/75s**，累计等待约 50 分钟；同镜像站的 redis/minio/alpine 均秒级成功（说明是个别大镜像层的问题） |
| 替代 | 在 WSL Ubuntu 24.04 里建**独立 MySQL 实例**：8.0.46，独立 datadir `/opt/adguard/mysql/data`，端口 3307，systemd unit `adguard-mysql.service`，账号 `adguard/adguard`，库 `adguard`（utf8mb4_0900_ai_ci）。**未触碰** WSL 中原有的 3306 实例 |
| 影响 | 服务代码、Flyway 迁移、SQL 语义、字符集与 compose 方案完全一致（同一 MySQL 8.0 大版本）；差异仅在"进程跑在哪" |
| 复现要求 | WSL 需要保持运行（`wsl -d Ubuntu -u root -- sleep infinity` 常驻），否则连接被拒 |
| 关闭计划 | TODO-M1-1 已关闭（2026-11-25）：RuleFlowIT 4/4 通过，`ci.ps1 -Full` PASS |

### 4.2 Testcontainers 集成测试（2026-11-25 已补跑）

`RuleFlowIT`（4 个场景：创建→改版→激活→快照校验、无激活规则拒绝、未知租户 404、租户隔离）已补跑：Testcontainers 拉取真实 `mysql:8.0` 容器（Flyway V1–V3 自动迁移），**Tests run: 4, Failures: 0, Errors: 0**，耗时 139.3s；`scripts/ci.ps1 -Full` 全量通过（含 java integration tests 步骤）。镜像拉取阻塞的解决办法：使用 `docker.m.daocloud.io/library/mysql:8.0` 镜像，再 `docker tag` 为 `mysql:8.0`（Docker Hub 直连大层下载卡住）。

### 4.3 PowerShell 5.1 编码坑（已修）

`smoke-m1.ps1` / `env.ps1` 含中文，PS 5.1 按 ANSI 读取无 BOM 的 UTF-8 → 解析失败。已改为 **UTF-8 with BOM**，并在运行手册注明。

## 五、已知限制（M1 固有，不是缺陷）

| # | 限制 | 影响 | 计划 |
|---|---|---|---|
| 1 | stub judge 一律判 `manual` 且无违规明细 | 无法演示"拦截"结论 | M4 真实模型 + M2/M3 规则引擎接入 |
| 2 | `/internal/rules/snapshot` 无鉴权 | 仅受信网络可用 | M6 加服务令牌/mTLS |
| 3 | 网关限流是单实例内存固定窗口 | 多副本时限额不共享 | M6 换 Redis 限流 |
| 4 | 快照是全量快照 | 规则万级时体积大 | M3 评估增量快照 |
| 5 | `complete` 会回读整个对象算 sha256（读放大） | 100 MB 素材多一次 I/O | M5 若成瓶颈改客户端声明 digest + ETag 校验 |
| 6 | 临时分片对象删除是尽力而为 | 极端故障下残留 | M3 加清理任务 |
| 7 | 队列投递失败不回滚上传（返回 202+warning） | 需要 sweeper 兜底 | M3 加 sweeper |

## 六、下一步（M2 法规结构化）

M2 验收（PRD，不降标）：

1. **规则模型扩展**：家族词典、检测条件（词法 AST / 语义 prompt / 豁免）、罚则、生效期、图文一致性断言 schema；
2. **7 类变形归一化管线**：NFKC → 零宽/emoji 剥离 → 繁简统一 → 异体字映射 → 拼音回填 → AC 自动机粗筛 → 语义精排，且**保留原文 offset 映射**；
3. **变体测试集 ≥1000 条**（按 7 类变形族均衡 + 对抗样本）；
4. **条款解析器**：法规文本 → 结构化规则（条文号/词族/条件/罚则），人工抽检；
5. **验收**：变体命中率 **≥ 0.95**；条款解析人工抽检准确率 **≥ 90%**。

技术选型预案（M2 启动时给出取舍表）：归一化与条款解析放 Python 服务（`pypinyin` / `opencc` / 正则 AST 生态成熟），Go 网关保持只做接入与编排。
