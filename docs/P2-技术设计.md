# P2 技术设计：营销素材合规审核平台

> 项目代号：**AdGuard**
> 场景：互联网平台商业化内容风控，日均新增营销素材百万级
> 底座：腾讯 WeKnora（Go）+ 阿里 Spring AI Alibaba（Java）+ LLaMA-Factory / TRL / veRL / vLLM / SGLang（Python）
> 法律依据：《广告法》第九条第（三）项、第五十七条，《广告绝对化用语执法指南》（2023 年第 6 号）

---

## 1. 设计目标与非目标

### 目标

| # | 目标 | 可验证标准 |
|---|---|---|
| G1 | 分钟级出结论 | P99 ≤ 60s（视频类 ≤ 5 min） |
| G2 | 高召回、低误杀 | 违规召回 ≥ 0.95，误杀 ≤ 0.03 |
| G3 | **结论可执法** | 条款级依据命中率 100%（rule_id + 原文 span） |
| G4 | 单位成本可控 | 单条推理成本 ≤ 目标线（实测 GPU 折旧/条） |
| G5 | 新规分钟级生效 | 规则入库→生效 ≤ 5 min，无需重建索引 |
| G6 | 私有化 | 全链路不出内网，模型自建 |

### 非目标

- 不做人工复审替代（AI 出初审，人做终审）
- 不做舆情/公关判断（只做合规判定）

## 3. 核心设计一：法规条款结构化（自研，底座不提供）

这是整个项目的地基。法规不是"一段文本"，是**带判定逻辑的结构**。

### 3.1 规则模型

```json
{
  "rule_id": "ADV-LAW-ART9-3",
  "law": "中华人民共和国广告法",
  "article": "第九条",
  "item": "（三）",
  "text": "不得使用'国家级'、'最高级'、'最佳'等用语",
  "family": "absolute_terms",
  "canonical_terms": ["最好", "最佳", "最高级", "国家级", "第一", "顶级", "唯一"],
  "detection": {
    "lexical": ["regex:最[好佳优低高强]", "ac_automaton:家族词典"],
    "semantic": "prompt:判断该表述是否构成对商品性能的绝对化宣称",
    "context_exemptions": ["本店销量第一（有据可查的历史事实）需附证明"]
  },
  "penalty": {"law_ref": "第五十七条", "min": 200000, "max": 1000000},
  "severity": "high",
  "effective_from": "2015-09-01",
  "effective_to": null,
  "source_url": "..."
}
```

**关键字段说明**

- `family`：把散落的词归成"禁用词族"，新规只需改族，不用改代码
- `context_exemptions`：合规判定必须看语境。"销量第一"若企业能举证历史数据，属可抗辩
- `penalty`：让结论能直接说"这条违反第 57 条，罚款区间 20–100 万"——法务认的是这个

### 3.2 变形对抗（本项目最硬的技术点之一）

关键词库永远追不上变体。必须做**归一化对抗**：

| 变形手法 | 例子 | 归一化手段 |
|---|---|---|
| 拼音 | `zui hao` | 拼音还原 + 声调剥离 |
| 拆字 | `冣`（最的异体） | 异体字/同形字映射表 |
| 谐音 | `醉好` | 音近词表 + 语义判定兜底 |
| emoji 间隔 | `最😀好` | 剥离非文字符号 |
| 零宽字符 | `最\u200b好` | 剥离 zero-width |
| 全半角 / 繁简 | `朂` / `最` | NFKC + 繁简转换 |
| 文言/同义替换 | `无出其右` | 语义相似度 + 家族扩展 |
| 图文分离 | 图上写"最"，文案不写 | OCR 后合并判定 |

**处理管线**

```
raw_text
 → NFKC 归一化
 → 剥离 zero-width / 控制字符 / emoji 装饰
 → 繁简统一
 → 同形字/异体字映射
 → 拼音回填（对疑似拼音串）
 → 关键词 AC 自动机粗筛（召回优先）
 → 语义判定精排（小模型）
 → 输出 span 定位
```

> 设计取舍：**粗筛只求召回，反正误报后面有语义模型和人工兜底**；但如果粗筛漏了，后面再强也救不回来。

### 3.3 图文一致性

极限词只是第一层。第二层是**图文不一致**：

1. OCR 抽出图上文字与区域 bbox
2. 从文案与图中分别抽取**属性断言三元组**：`(主体, 属性, 值)`
3. 冲突检测：同一主体同一属性出现互斥值 → 违规

例：图里写"产地：意大利"，文案写"国产直供" → `(商品, 产地, 意大利)` vs `(商品, 产地, 中国)` → 冲突。

> 这一层是纯向量检索做不到的，必须靠结构化断言抽取。

## 4. 核心设计二：知识工程流水线

```
素材/规则入库
  → 文档解析（PDF/DOCX/图片/网页渲染）
  → 条款级切分（按"第X条"锚点 + 标题层级）
  → 结构化（rule_id / 条款号 / 判定条件 / 罚则）
  → Embedding（多粒度：条款级 + 子句级）
  → 多路索引（向量 + BM25 + 规则树 + 家族词典）
  → 增量更新（事件驱动）
  → 检索评测（Recall@K / NDCG@10）
```

### 4.1 条款级切分的必要性

段落级切分会把"违约金 5%"从一个完全无关的条款里捞出来，污染判定。条款级切分保证**召回结果的语义边界与法律边界对齐**。

### 4.2 增量索引（对应 T2 消息队列项）

| 事件 | 动作 |
|---|---|
| 新规发布 | 解析 → 结构化 → 写库 → 发 `rule.updated` 事件 |
| Embedding 模型升级 | 后台双写新索引 → 影子比对 → 切换 |
| 素材删除/下架 | 逻辑删除，索引标记过期 |

**关键正确性问题**（WeKnora 已验证有对应设计）：chunk 内容变更后，旧的召回结果必须被丢弃。WeKnora 的 `TestRerankEnrichmentDropsChangedChunkRevision` 正是在验证这件事——**当前代码里 chunk revision 校验会丢弃已变更的召回**。

### 4.3 混合检索 + Rerank

复用 WeKnora 的链路：

```
query
 → 向量召回 topK1
 → BM25 召回 topK2
 → 规则树命中（精确匹配 rule_id）
 → 合并去重
 → Rerank（多厂商协议：cohere / dashscope / pinecone / volcengine / tei）
 → 阈值过滤（filterScores）
 → 返回条款级结果 + span
```

## 5. 核心设计三：模型工程流水线

### 5.1 三阶段

```
阶段一 SFT      教师标注集 → LoRA/QLoRA 微调 7B/8B
阶段二 DPO      人工复审裁决 → 偏好对 → DPO 对齐
阶段三 蒸馏     教师模型精标 → 1.5B/3B 小模型 → 量化部署
```

### 5.2 DPO 偏好对从哪来（关键：不是造数据）

```
初审判定 J1  →  人工复审改为 J2
=> 偏好对 (chosen=J2, rejected=J1)
```

这是**业务副产品**，每天自然产生。抽取条件：
- 初审与复审结论不同
- 复审有明确理由标签（漏放/误杀/依据不足）
- 同一 rule family 下样本均衡（防偏置）

### 5.3 蒸馏的 ROI 账

| 方案 | 单条成本 | 日均百万条成本 | 结论 |
|---|---|---|---|
| 大模型 API | 高 | 不可接受 | ❌ |
| 7B 自建 vLLM | 中 | 偏高 | 仅用于教师/疑难 |
| 1.5–3B 蒸馏后 | 低 | 可接受 | ✅ 主力 |

> 这也解释了为什么必须私有化：**不是技术偏好，是算不过账**。

### 5.4 训练与推理栈

| 环节 | 选型 | 说明 |
|---|---|---|
| SFT | LLaMA-Factory（`hiyouga/LlamaFactory`） | 支持 LoRA/QLoRA，配置化 |
| DPO | TRL | `DPOTrainer` 成熟 |
| RL（GRPO） | veRL（`verl-project/verl`） | 可选进阶，对应 T1 第 27 项 |
| 推理主引擎 | vLLM | PagedAttention、连续批处理 |
| 推理对照 | SGLang | 做双引擎吞吐/延迟对比，产出压测结论 |

## 6. 控制面（Java）

| 模块 | 职责 |
|---|---|
| 租户 | 事业部隔离，数据与规则可独立 |
| 规则库 | 规则 CRUD、版本、灰度生效、回滚 |
| 审批流 | 高风险判定的二次确认 |
| 配额计费 | 按调用量配额，成本归集到租户 |
| 审计 | 谁在何时改了哪条规则、哪次判定被谁推翻 |
| 规则快照 | 向推理侧下发不可变快照，保证判定可复现 |

**关键设计：判定必须绑定规则版本快照**
一次判定记录 `rule_snapshot_id`。半年后回查"当时为什么这么判"，能完整复现，不受后续规则变更影响。

## 7. 数据模型

```sql
-- 素材
CREATE TABLE asset (
  id CHAR(36) PRIMARY KEY, tenant_id VARCHAR(64),
  type ENUM('image','video','text','landing_page'),
  uri TEXT, digest CHAR(64), status VARCHAR(32), created_at DATETIME
);

-- 规则与版本
CREATE TABLE rule (
  rule_id VARCHAR(64) PRIMARY KEY, law VARCHAR(128), article VARCHAR(32),
  item VARCHAR(16), family VARCHAR(64), severity ENUM('high','mid','low'),
  penalty_min INT, penalty_max INT, effective_from DATE, effective_to DATE NULL,
  source_url TEXT
);
CREATE TABLE rule_version (
  id CHAR(36) PRIMARY KEY, snapshot_id CHAR(36),
  payload JSON, created_by VARCHAR(64), created_at DATETIME, status ENUM('draft','active','retired')
);

-- 判定
CREATE TABLE judgment (
  id CHAR(36) PRIMARY KEY, asset_id CHAR(36), tenant_id VARCHAR(64),
  rule_snapshot_id CHAR(36), model_version VARCHAR(64),
  decision ENUM('pass','block','manual'),
  latency_ms INT, cost_micro BIGINT, created_at DATETIME
);

-- 违规明细（条款级）
CREATE TABLE violation (
  id CHAR(36) PRIMARY KEY, judgment_id CHAR(36), rule_id VARCHAR(64),
  span_start INT, span_end INT, bbox JSON,
  evidence_text TEXT, confidence DECIMAL(3,2)
);

-- 申诉与偏好对
CREATE TABLE appeal (
  id CHAR(36) PRIMARY KEY, judgment_id CHAR(36),
  reason VARCHAR(64), status ENUM('open','accepted','rejected'),
  reviewer VARCHAR(64), final_decision VARCHAR(16), created_at DATETIME
);
CREATE TABLE feedback_pair (
  id CHAR(36) PRIMARY KEY, judgment_id CHAR(36),
  chosen JSON, rejected JSON, family VARCHAR(64),
  used_in_dpo TINYINT DEFAULT 0
);
```

## 9. 评测方案

### 9.1 数据集

| 集合 | 规模 | 来源 |
|---|---|---|
| 违规集 | 3,000 | 历史人工判例 + 合成变体（拼音/拆字/谐音/emoji 各族均衡） |
| 合规集 | 3,000 | 正常素材，考察误杀 |
| 边界集 | 1,000 | 有豁免情形、需语境判断的样本 |
| 对抗集 | 1,000 | 专门构造的变形样本 |

### 9.2 指标

| 指标 | 目标 |
|---|---|
| 违规召回率 | ≥ 0.95 |
| 误杀率 | ≤ 0.03 |
| 条款级依据命中率 | 100% |
| P99 时延 | ≤ 60s |
| 单条推理成本 | 实测并给出容量结论 |
| 规则热更新生效时延 | ≤ 5 min |
| 蒸馏后 vs 教师 | 召回下降 ≤ 3pt |

### 9.3 门禁

新模型上线前必须过：召回不降、误杀不升、条款命中 100%，否则阻断。

## 12. 风险与降级

| 风险 | 降级 |
|---|---|
| 变体对抗做不完（攻击面无限） | 只承诺"已知变体族覆盖"，未知变体靠语义模型 + 人工抽检 |
| 标注数据不足 | 用规则 + 教师模型合成，再人工校验关键集 |
| DPO 效果不稳定 | 退回 SFT + 规则融合，DPO 作为可选增强 |
| 蒸馏掉点过多 | 提高学生模型尺寸或保留教师兜底路由（高疑难度走大模型） |
| 规则热更新引发判定漂移 | 快照版本化 + 每日回放对比，漂移超阈值自动回滚 |
| GPU 成本超预期 | 批处理 + 量化 + 动态降级（低风险素材走小模型） |
